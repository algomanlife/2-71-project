# secp256k1 Implementation Comparison — Research Evaluation

Date: 2026-11-05 · Purpose: standalone research comparison only. **No
candidate is integrated into the project's search pipeline** (binding
scope rule; the search engine's math is frozen pending the evidence-gated
optimization program).

## Candidates

### 1. Correctness-first reference (project-internal)

`research/cuda-lab/include/lab/secp_ref.cuh` — the project's own
secp256k1 field arithmetic and affine EC ops, **extracted verbatim** for
isolated characterization.

- Provenance: VanitySearch (GPL-3.0) / VanitySearch-Bitcrack (AGPL-3.0)
  via CUDACyclone (see ATTRIBUTION.md).
- CUDA: yes (written for GPU, inline-PTX carry chains).
- sm_120 compile: ✅ (CI lab build).
- Correctness: ✅ public vectors in the lab (2G/3G/7G/k·G, modmul
  chains) — generated by independent python `ecdsa`.
- Single-op latency / batch throughput: measured via lab benches
  (`modmul256`, `ec-scalar-mul`) — **runtime pending** on the 5090 rig.
- License obligations: copyleft inherited (GPL-3.0/AGPL-3.0 upstream).

### 2. UltrafastSecp256k1 (shrec) — external

Repository: https://github.com/shrec/UltrafastSecp256k1 (61 stars,
actively maintained; author Vano Chkheidze).

| Criterion | Finding (verified via GitHub API / repo, 2026-11-05) |
|---|---|
| License | **MIT** — verified from the LICENSE file; permissive, compatible with evaluation and (license-wise) with any downstream choice |
| CUDA support | yes — `src/cuda` backend (+ OpenCL, Metal); "stable 13-op GPU C ABI (8 core + 5 batch ops)" |
| sm_120 compilation | **not yet verified** — requires CUDA toolkit ≥ 3.18 CMake, C++20; must be attempted on the rig before any claim |
| API design | single ops + batch ops (GPU ABI); libsecp256k1 compat shims (opt-in) |
| Correctness | public-vector verification REQUIRED before any use; repo self-describes as having **no external third-party security audit** (self-generated CAAS evidence only) |
| Performance | self-reported CPU-side numbers (~1.5× vs libsecp256k1 for some paths); **CPU speed does not imply GPU speed — must be measured** |
| Memory | not yet measured |
| Build requirements | CMake ≥ 3.18, C++20 (GCC 11+/Clang 15+); no runtime deps for CPU build |
| Maintenance/portability | broad platform matrix (12+); production usage mentioned (SparrowWallet Frigate) |

Preliminary assessment: **evaluation candidate only**. MIT licensing is
compatible; but (a) no external audit, (b) GPU backend is a separate
review profile, (c) zero measured data on our hardware. Decision on any
use belongs to a future, explicitly-scoped phase — never silently into
the search engine.

### 3. Independent CPU reference (validation only)

Python `ecdsa` package (v0.19.2, requirements.txt) — used as the
independent oracle for all test vectors; not a performance candidate.

## Comparison protocol (when hardware is available)

1. Build each candidate on the 5090 rig (CUDA 13.4); record toolchain.
2. Correctness first: public vectors (RFC-style EC vectors + our lab
   vectors); any mismatch disqualifies.
3. Single-op latency and batch throughput via the lab runner
   (`research/cuda-lab/scripts/run_experiments.py`): ≥ 5 reps, medians +
   stdev, identical launch geometry across candidates.
4. Record memory consumption (nvidia-smi during runs).
5. Report in `OPTIMIZATION_RESULTS.md`; never extrapolate CPU numbers
   to GPU.
